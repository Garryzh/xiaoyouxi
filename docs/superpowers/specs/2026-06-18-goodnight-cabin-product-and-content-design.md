# 《晚安，小屋》产品与内容系统设计规格

版本：1.0  
日期：2026-06-18  
状态：待用户最终审阅  
适用范围：产品体验、视觉素材、陪伴文案、原创音乐、商业化与后续 Skill 建设

## 1. 产品定位

《晚安，小屋》是一款竖屏、轻量、睡前使用的治愈陪伴与房间装扮小游戏。

产品不是依靠竞争、排行或连续签到推动玩家，而是通过以下价值让玩家愿意回来：

1. 被记得：伙伴会称呼玩家的小名，并记得近期情绪、日记和共同经历。
2. 被理解：回应以共情和陪伴为主，不说教、不诊断、不假装替代现实关系。
3. 有变化：房间、伙伴动作、纸条、音乐和小礼物会持续产生温和惊喜。
4. 能创造：玩家可以装扮自己的夜间小屋，形成个人空间和收藏目标。
5. 感到安全：错过登录不会失去奖励，不以焦虑或情感绑架推动付费。

一句话体验承诺：

> 每天睡前回到一间记得你的小屋，和一位温柔的小伙伴说说话，再带走一点不期而遇的暖意。

## 2. 目标用户与使用场景

### 2.1 核心用户

- 睡前需要放松、安静陪伴或简单情绪出口的人。
- 喜欢可爱动物、房间装扮、收藏和治愈系插画的人。
- 不喜欢高压力任务、竞技、复杂养成和强制签到的人。

### 2.2 核心场景

- 睡前 3–10 分钟短时使用。
- 情绪低落、疲惫或想记录当天感受时。
- 想查看伙伴准备的新纸条、礼物或房间变化时。
- 想整理房间、收集家具或切换音乐氛围时。

## 3. 核心体验循环

### 3.1 每日循环

1. 玩家进入小屋。
2. 伙伴根据时间、玩家昵称、近期情绪和日记给出自然问候。
3. 玩家选择聊天、记录情绪、写日记或直接停留听音乐。
4. 系统给予星光、纸条、家具互动或小礼物之一。
5. 玩家使用免费所得或直接购买的装扮调整房间。
6. 伙伴对新摆设或当天经历作出反馈。
7. 玩家以一句晚安、音乐定时或安静陪伴结束本次体验。

### 3.2 长期循环

- 共同陪伴天数解锁纪念剧情，但不因中断而清零。
- 房间互动逐步解锁伙伴回忆和彩蛋。
- 免费游玩持续获得基础家具和收藏。
- 每月增加主题收藏、原创音乐与少量新剧情。
- 付费扩展外观和氛围，不扩展“被关心的程度”。

## 4. 首次进入与命名

### 4.1 玩家昵称

- 首次进入必须填写昵称或小名。
- 提示语为：“请告诉我，你喜欢被怎么称呼？”
- 长度限制为 1–10 个可见字符。
- 后续可在设置中修改。
- 首版默认保存在本地。
- 对话适度使用昵称，不在每句话中重复称呼。

### 4.2 伙伴选择与命名

首发提供三种伙伴：

| 伙伴 | 基础性格 | 表达特点 |
|---|---|---|
| 小熊 | 安稳、可靠 | 更擅长肯定、安抚和陪着慢下来 |
| 小猫 | 活泼、细腻 | 更容易注意细节，用轻巧方式改善情绪 |
| 小兔 | 安静、柔软 | 话较少，善用停顿、观察和温柔回应 |

- 三位伙伴核心功能相同。
- 每位伙伴拥有专属语气、动作和少量专属剧情。
- 玩家选择后必须为伙伴命名，默认名称可保留为“小夜”。
- 伙伴名称可在设置中修改。

## 5. 视觉风格宪法

本节是后续美术生产不可随意修改的强制规则。任何更改都需要重新确认。

### 5.1 核心风格

- 2D 手绘治愈系游戏插画。
- 正面娃娃屋视角。
- 手机竖屏 9:16。
- 圆润轮廓、柔和手绘线稿、轻微纸张颗粒。
- 低对比暖光，夜晚但不昏暗压抑。
- 温馨但不低幼，细腻但不过度复杂。

### 5.2 色彩

- 主色：奶油米色、蜜糖橙、雾霾蓝。
- 辅助色：森林绿、樱花粉、薰衣草紫。
- 视觉重点使用暖黄色灯光。
- 大面积区域避免纯黑、纯白和高饱和霓虹色。
- 同一画面主要色相不超过四组，确保安静统一。

### 5.3 伙伴造型

- 可爱小动物外形，使用人类朋友般的表达方式。
- 圆头、短手脚、睡衣造型。
- 角色高度约占房间画面高度的四分之一。
- 三位伙伴保持相同头身比例、线条粗细、眼睛结构和材质表现。
- 表情应清楚但克制，避免夸张漫画式五官变形。

### 5.4 房间与家具

- 房间固定使用正面娃娃屋视角。
- 家具轮廓和接触面必须清楚，能独立切图和摆放。
- 房间、家具和角色共用一致的透视、光源方向和阴影软硬度。
- 房间背景不自带不可拆分的前景家具，空房间必须可用于编辑。
- 家具不附带文字、价格、水印、外框或复杂背景。

### 5.5 禁止项

- 写实摄影感。
- 3D 塑料玩具感。
- 高饱和霓虹配色。
- 强烈硬阴影和恐怖氛围。
- 过度幼儿化、廉价贴纸感。
- 同批次出现不同线条、材质、透视或角色比例。
- 画面自带文字、水印、品牌标志和不可控签名。

## 6. 首发房间系统

首版统一为夜晚，不制作白天版本。每个房间配置一种低干扰动态氛围。

| 编号 | 房间 | 动态氛围 | 情绪关键词 |
|---|---|---|---|
| ROOM-01 | 星光卧室 | 窗外星光缓慢闪烁 | 安全、初见、柔软 |
| ROOM-02 | 森林树屋 | 萤火虫缓慢漂浮 | 自然、呼吸、隐秘 |
| ROOM-03 | 温暖雨夜 | 玻璃雨滴与远处雨幕 | 包裹、安静、倾听 |
| ROOM-04 | 冬日雪屋 | 窗外细雪缓慢落下 | 洁净、宁静、依偎 |
| ROOM-05 | 壁炉客厅 | 壁炉光轻微跳动 | 团聚、温暖、可靠 |
| ROOM-06 | 月光阁楼 | 星云与月光微动 | 想象、秘密、梦境 |

每套房间必须提供：

- 2160×3840、9:16 无损母版。
- 游戏使用的压缩 WebP。
- 可编辑空房间版本。
- 家具摆放安全区域参考图。
- 商店或选择页缩略图。
- 动态氛围所需的独立前景或动画图层。

海边灯塔与云朵梦境房不进入首发范围，作为后续主题候选。

- 首页顶部信息区与底部导航。
- 对话气泡、情绪状态和伙伴头像。
- 日记本、信件、签到纪念册。
- 星光货币图标。
- 商店分类、商品卡和套装封面。
- 礼物、纪念物、宝箱与解锁画面。

UI 组件遵循同一色彩和线条规范，但必须优先保证文字清晰度与触控可用性，不能为了装饰牺牲操作识别。

## 9. 陪伴文案系统

### 9.1 首版规模

首版准备约 300 条基础语句：

| 类型 | 数量 |
|---|---:|
| 日常问候 | 60 |
| 情绪回应 | 90 |
| 日记回应 | 60 |
| 回归陪伴 | 30 |
| 家具互动 | 30 |
| 礼物与惊喜 | 30 |

基础语义可共享，但三位伙伴应按各自性格改写表达。不能仅替换伙伴名称。

### 9.2 文案原则

- 使用玩家设置的昵称或小名，但避免每句重复。
- 先回应情绪，再给选择，不急于提供建议。
- 句子短、口语化、自然，适合手机气泡阅读。
- 允许安静陪伴，例如：“如果你不想说，我们就坐一会儿。”
- 可引用玩家当天主动记录的情绪和日记摘要。
- 不擅自推断未表达的创伤、疾病、关系或生活事实。
- 不做心理诊断，不扮演医生，不承诺治疗结果。
- 不制造排他关系，不表达“只有我懂你”或阻止玩家寻求现实帮助。
- 涉及自伤、自杀或现实危险时，停止普通陪伴脚本，转入清晰、尊重且鼓励现实求助的安全流程。

### 9.3 温馨语句触点

- 进入房间时的主动问候。
- 玩家提交情绪或日记后的回应。
- 点击伙伴时的短句。
- 点击家具触发的回忆或观察。
- 收到礼物时附带的小纸条。
- 多日未进入后的欢迎语。
- 音乐定时结束前的晚安语。

## 10. 原创音乐与声音系统

首版配置：

- 1 首大厅主题曲。
- 6 个房间各 1 首可无缝循环的原创音乐。
- 6 组环境音：雨声、细雪风声、壁炉、森林虫鸣、钟表和夜空风声。
- 基础交互音效：点击、购买、摆放、解锁、礼物、信件和晚安。

要求：

- 音乐与环境音可独立调节。
- 提供 15、30、60 分钟和播放完当前曲目的睡眠定时选项。
- 循环点不可出现明显断裂、爆音或音量跳变。
- 音乐避免突发高频、强鼓点和过度悲伤的旋律推进。
- 全部音乐原创，并保留工程文件、导出母版、作者信息和完整商用版权记录。
- 使用 AI 辅助时也必须确认训练、生成与商用条款，不使用来源不明素材。

## 11. 持续惊喜与留存机制

### 11.1 惊喜来源

- 每日随机小纸条或小礼物。
- 共同陪伴里程碑解锁纪念剧情。
- 家具互动偶尔触发彩蛋。
- 伙伴根据日记内容准备非物质回应。
- 每月新增一组主题收藏。
- 新房间、服装或原创音乐解锁时提供小型展示演出。

### 11.2 无焦虑规则

- 不强制每日签到。
- 中断登录不清零陪伴天数和累计进度。
- 错过活动不永久剥夺核心内容。
- 不使用红点轰炸、倒计时威胁或“伙伴很失望”等催回话术。
- 随机惊喜不与付费概率绑定。

## 12. 商业模式

核心原则：装扮付费，陪伴免费。

### 12.1 免费内容

- 三位首发伙伴的完整基础陪伴能力。
- 情绪记录、日记回应与核心温馨语句。
- 初始房间及持续可获得的免费家具。
- 基础原创音乐和环境音。
- 无付费门槛的惊喜、纪念剧情与安全支持。

### 12.2 付费内容

- 主题房间包：一次性直接购买。
- 家具套装：明码标价直接购买。
- 伙伴服装：明码标价直接购买。
- 可选月度会员：每月领取限定装扮、原创音乐和收藏品。

### 12.3 禁止模式

- 不出售“更关心你”或“更懂你”的对话能力。
- 不做抽卡、付费概率宝箱和价格模糊的多层货币。
- 不强制观看广告。
- 不利用孤独、愧疚、断签焦虑或伙伴关系推动付费。
- 不让免费玩家面对功能残缺或无法完成房间装扮。

## 13. 图片生产与技术标准

### 13.1 文件规格

| 类型 | 母版规格 | 游戏格式 |
|---|---|---|
| 房间背景 | 2160×3840，9:16 | WebP |
| 伙伴角色 | 2048×2048，透明背景 | PNG/WebP |
| 家具素材 | 1024×1024，透明背景 | PNG/WebP |
| UI 图标 | 512×512，透明背景 | PNG 或 SVG |

- 同时保留无损母版和压缩游戏版。
- 所有透明素材必须清理白边、黑边、残影和半透明脏像素。
- 游戏版在目标手机分辨率下检查清晰度和文件大小。

### 13.2 命名规则

统一使用：

`GC_类别_主题_对象_状态_版本`

示例：

- `GC_CHAR_BEAR_IDLE_V01`
- `GC_ROOM_STARLIGHT_EMPTY_V01`
- `GC_FURN_RAIN_LAMP_ON_V01`
- `GC_UI_GIFT_LOCKED_V01`
- `GC_MUSIC_FOREST_NIGHT_V01`

文件名使用英文大写与下划线。中文名称记录在素材清单中，不直接用于程序资源路径。

### 13.3 可复现记录

每个 AI 辅助素材都要记录：

- 素材编号与版本。
- 正向提示词。
- 负面提示词。
- 使用模型与模型版本。
- 参考图编号。
- 种子或可复现参数。
- 生成日期。
- 人工修改说明。
- 验收结果和返工历史。

## 14. 风格锚点样张

在批量生产前只制作以下锚点样张：

1. 小熊、小猫和小兔的统一角色设定图。
2. 星光卧室空房间。
3. 六件代表性家具：床、灯、桌、座椅、装饰品、惊喜物件。
4. 一张包含角色、家具、对话和 UI 的实际首页组合效果图。

锚点未通过前，不得批量生成其他房间和家具。

### 14.1 锚点验收

必须同时满足：

1. 三位伙伴看起来属于同一个世界。
2. 房间第一眼传达安全、温暖和愿意停留的感受。
3. 缩小到手机实际尺寸后，角色和家具仍能辨认。
4. 家具放进不同房间时不存在明显透视与光线冲突。
5. 连续生成时线条、材质和色彩无明显漂移。
6. 首页组合图达到愿意截图分享的完成度。
7. 两轮独立体验测试中，至少 80% 的测试者选择“温馨、可爱、治愈”。

## 15. 七道素材生产门禁

所有图片必须依次通过：

1. 风格一致性：符合视觉风格宪法。
2. 构图与透视：符合娃娃屋视角及摆放逻辑。
3. 角色比例：角色、家具和房间比例一致。
4. 光源与配色：光线方向、色温和主色符合目标房间。
5. 技术质量：透明边缘、尺寸、格式和命名正确。
6. 手机预览：在 9:16 实际界面中清楚、可操作、不遮挡。
7. 人工确认：由用户最终批准后入库。

任一门禁失败，素材必须返工，不能直接进入游戏。

### 16.2 总控职责

- 检查新需求是否符合产品定位和世界观。
- 检查是否违反风格、情绪安全、技术规格或商业化原则。
- 选择并加载所需专业规范。
- 输出统一的制作任务和验收要求。
- 管理素材编号、版本、提示词和返工记录。

### 16.3 冲突处理

发现冲突时必须停止生产，并输出：

1. 冲突原因。
2. 影响范围。
3. 两个可行修正方案。

只有用户确认修正方案后才能继续。

### 16.4 固定输出结构

每次接收素材需求后固定输出：

1. 素材规格卡。
2. 统一正向提示词。
3. 负面提示词。
4. 尺寸、格式与透明背景要求。
5. 与现有角色、房间和世界观的关联约束。
6. 七道门禁验收表。
7. 不合格时的定向返工提示词。
8. 素材编号、版本和文件名。

### 16.5 标准工作流

1. 接收需求。
2. 执行世界观与商业原则冲突检查。
3. 输出素材规格卡。
4. 输出提示词与负面提示词。
5. 制作低成本预览稿。
6. 用户批准预览稿。
7. 生成高清母版。
8. 执行七道验收门禁。
9. 执行手机端组合测试。
10. 用户最终确认后入库。
11. 记录提示词、版本和返工历史。

任何阶段未确认，不得跳到下一阶段。

## 18. 产品成功指标

首轮测试重点验证产品价值，不以收入作为唯一标准：

- 首次体验完成率：完成昵称、伙伴选择并进入房间。
- 首日核心循环完成率：至少完成一次互动或日记，并领取一次惊喜。
- 7 日内自愿回访率：不依靠强制签到提醒。
- 对话温暖度评分。
- 房间与家具吸引力评分。
- 音乐舒适度与继续停留意愿。
- 测试者能否准确理解付费仅用于装扮与内容扩展。

具体数值目标在封闭测试样本量确定后写入测试计划，避免在缺少基线时设定虚假精确指标。
